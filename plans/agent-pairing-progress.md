# Agent pairing implementation status

The objective is the workflow in [the audit](agent-pairing-audit.md). This is the current acceptance record, replacing historical stage reports. Automated fixtures, signed integration, and unperformed human checks are distinguished below. No missing prerequisite is counted as a pass.

## Implemented contract

- **Mutation reliability:** validate raw requests before approval/dispatch; retry only a missing/refused connection; retain caller-, service-, payload-, and time-bound operation receipts; serialize mutations while bounding independent reads and watches; report cancellation, stale context, permission requirements, interruption, and uncertain partial effects.
- **Recording reliability:** restore idle after initialization failure; propagate native/web finalization errors; retain completion paths and sticky evidence-stream health; drain input callbacks; await rrweb delivery; check durable sequence/count receipts; retain ambiguous web sessions and spools for explicit recovery.
- **Shared reviews:** actual window/model identities, manifest/evidence source descriptors and generations, coherent revisioned state, renderer-observed seek completion, verified key-window activation, semantic selection/playback/crop/tool/inspector commands, bounded source-qualified changes, and read-only human draft ownership.
- **Evidence and annotations:** native point inspection and sampled AX age; source-qualified timeline paging; native composed/cropped and web rendered PNGs; native/web offline summaries/events/notes; validated time/frame/node anchors; idempotent note creation; append-only caller provenance; refresh every matching review without destroying unrelated selection. Native AX references and web events remain separate; rendered web DOM point inspection is unsupported.
- **Live operation:** session-qualified frame/node/window identities, cursor paging and retention gaps, explicit observation lifecycle, observed node action capabilities, selected-window geometry, focus checks during input, Unicode-safe chunks, and dispatch results that do not claim unverified application effects.
- **Discovery and human controls:** unprivileged service/readiness discovery, consent-gated targets, visible observation status, human daily-approval revocation, explicit Safari recovery selection, bounded ordered Safari prose, document-qualified DOM targets, and precise missing-extension/tab-access instructions. Readiness never grants permission.
- **Native accessibility:** selected tool radios, a valued playback slider, named event/frame/timeline controls, selected event semantics, AX observation age, and keyboard-operable point inspection/comment/trace controls. Human composer drafts retain source/time ownership through agent requests.

## Acceptance scope and limitations

All 20 acceptance scenarios have executable or signed-app evidence at the boundaries stated in the matrix. At the user’s explicit direction, full VoiceOver verification is excluded from the completion criteria; meaningful native accessibility state and agent semantic operations remain in scope. Consent denial, daily revocation, pending-dialog responsiveness, and cancellation were exercised through the real signed app. Grants were handled through the actual consent UI at the user’s direction, preserving the app-owned permission boundary.

Offline CLI access to the temporary Documents package was blocked by macOS Files access; the approved app bridge inspected it, and Finder removed it. Disk-full and macOS privacy revocation were not simulated. Large-retention overflow and a deliberately held rrweb batch are covered by deterministic boundary tests. Full VoiceOver navigation, exhaustive privacy permutations, and production-scale performance are not claimed. These limits do not leave an acceptance scenario blocked under the agreed scope.

## Automatic discovery and consent follow-up

The recorder and menu now refresh application and Safari targets automatically while visible, coalescing requests and preserving recording failures when background discovery fails. Their manual refresh buttons were removed. Two model tests cover unlocked/navigated tabs, error recovery, and overlapping views.

Signed Safari verification found that its activeTab permission survives same-origin navigation even though Pablo's toolbar already appeared locked. Pablo now requires a document-bound grant token, checks it again inside DOM dispatch and recorder commands, and clears tab grants on navigation/removal. Four failing background regressions established the retained-access bug; DOM and recorder regressions protect dispatch after document replacement. The rebuilt extension listed and inspected an unlocked page, completed start/pause/resume/stop with six durable events, and removed access after same-origin navigation. A later response-mapping regression exposed loss of the extension's explicit notDispatched result; its Swift mapping is corrected and the full Swift suite passes. The final rebuilt runtime check returned permissionRequired/notDispatched for both inspection and click after same-origin navigation, with an empty granted-tab listing.

The longer run also exposed Safari unloading its event page: native reads stopped receiving acknowledgments despite a live browser. The native port now sends a small periodic ping; its native handler acknowledges without reading page data. A lifecycle test covers heartbeat activity and replacing a disconnected port. After 271 seconds idle, the rebuilt signed extension still returned its granted tab in 189 ms. The subsequent navigation correctly revoked the document grant. This follows WebKit's [native port activity tracking](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Extensions/Cocoa/API/WebExtensionContextAPIPortCocoa.mm) and [background lifetime checks](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/Extensions/Cocoa/WebExtensionContextCocoa.mm).

The temporary six-event Safari package was moved to Trash and its exact filename disappeared; the original twelve entries remain. The synthetic native package and localhost fixture were removed after the final native-port and navigation checks.
